# Термины и сокращения курса

В этом обзоре собраны ключевые термины, сокращения и принципы бэкэнд-курса с 1 недели по 15 сентября 2026 года. Изучите их значения самостоятельно и добавьте свои собственные заметки.

## Сокращения

| Термин | Краткое определение  |
|---|---|
| **API** | Application Programming Interface – интерфейс, через который программы обмениваются данными и функциями. |
| **URL** | Uniform Resource Locator – уникальный адрес ресурса в интернете. |
| **HTTP** | Hypertext Transfer Protocol – протокол для передачи данных в интернете. |
| **HTTPS** | Hypertext Transfer Protocol Secure – зашифрованная и безопасная версия HTTP. |
| **REST** | Representational State Transfer – архитектурный стиль для API, который управляет ресурсами через HTTP. |
| **CRUD** | Create, Read, Update, Delete – четыре основные операции: создание, чтение, изменение и удаление. |
| **JSON** | JavaScript Object Notation – текстовый формат для хранения и передачи данных. |
| **ESM** | ECMAScript Modules – современная модульная система JavaScript с `import` и `export`. |
| **CommonJS** | Common JavaScript – более старая система модулей Node.js с `require` и `module.exports`. |
| **npm** | Node Package Manager – менеджер пакетов для JavaScript и Node.js. |
| **REPL** | Read-Eval-Print Loop – среда, которая считывает и выполняет код, а затем показывает результат. |
| **SQL** | Structured Query Language – язык для управления реляционными базами данных. |
| **NoSQL** | Not Only SQL – общее название нереляционных систем баз данных. |
| **ORM** | Object-Relational Mapping – метод, представляющий таблицы базы данных в виде объектов в коде. |
| **ODM** | Object-Document Mapping – метод, представляющий документы базы данных в виде объектов. |
| **ACID** | Atomicity, Consistency, Isolation, Durability – четыре свойства, которые гарантируют надёжность транзакций. |
| **MVCC** | Multi-Version Concurrency Control – метод параллельного управления несколькими версиями данных. |
| **PK** | Primary Key – первичный ключ, который однозначно идентифицирует каждую запись. |
| **FK** | Foreign Key – внешний ключ, который связывает таблицы. |
| **1NF, 2NF, 3NF** | First, Second, Third Normal Form – уровни нормализации для хорошо структурированных таблиц. |
| **JWT** | JSON Web Token – подписанный токен, который может содержать информацию о пользователе. |
| **MFA** | Multi-Factor Authentication – вход как минимум с двумя различными факторами безопасности. |
| **2FA** | Two-Factor Authentication – вход с двумя факторами безопасности. |
| **TOTP** | Time-Based One-Time Password – ограниченный по времени одноразовый код для входа. |
| **OAuth 2.0** | Open Authorization 2.0 – стандарт, разрешающий ограниченный доступ к чужим ресурсам. |
| **OIDC** | OpenID Connect – уровень идентификации на основе OAuth 2.0. |
| **SSO** | Single Sign-On – один вход, который предоставляет доступ к нескольким приложениям. |
| **CSRF** | Cross-Site Request Forgery – атака, при которой пользователь непреднамеренно выполняет действие. |
| **XSS** | Cross-Site Scripting – атака, при которой вредоносный код внедряется в веб-страницу. |
| **CORS** | Cross-Origin Resource Sharing – правила, контролирующие доступ между разными источниками. |
| **OWASP** | Open Worldwide Application Security Project – организация, которая разрабатывает материалы и стандарты веб-безопасности. |
| **SDK** | Software Development Kit – набор инструментов для разработки под определённую платформу. |
| **SaaS** | Software as a Service – программное обеспечение, предоставляемое как онлайн-сервис. |
| **DBMS** | Database Management System – программное обеспечение для создания и управления базами данных. |

| **`next()`** | Передаёт запрос следующей middleware-функции. |
| **`next(err)`** | Передаёт ошибку центральному обработчику ошибок. |
| **JSON-Middleware** | JavaScript Object Notation Middleware – middleware, преобразующая JSON из тела запроса в объект. |

## HTTP, API и CRUD

| Термин | Краткое определение  |
|---|---|
| **Request** | Запрос, который клиент отправляет серверу. |
| **Response** | Ответ сервера на запрос. |
| **HTTP-Methode** | Hypertext Transfer Protocol Method – описывает нужное действие, например GET или POST. |
| **Endpunkt** | Конкретный URL-адрес API для определенной функции. |
| **Request-Body** | Часть запроса, содержащая отправленные данные. |
| **Header** | Метаданные о запросе или ответе. |
| **Statuscode** | Число, описывающее результат HTTP-запроса. |
| **`200 OK`** | Запрос выполнен успешно. |
| **`201 Created`** | Новый ресурс успешно создан. |
| **`204 No Content`** | Запрос выполнен успешно, но ответ не содержит данных. |
| **`400 Bad Request`** | Запрос содержит недопустимые или отсутствующие данные. |
| **`401 Unauthorized`** | Для запроса отсутствует действительная аутентификация. |
| **`403 Forbidden`** | Пользователь известен, но доступ ему не разрешён. |
| **`404 Not Found`** | Запрошенный ресурс не найден. |
| **`500 Internal Server Error`** | Произошла непредвиденная ошибка на сервере. |
| **REST-Ressource** | Representational State Transfer Resource – объект или запись, которой управляет REST API. |
| **`PUT`** | Обычно полностью заменяет ресурс. |
| **`PATCH`** | Обычно изменяет только отдельные части ресурса. |
| **404-Fallback** | Последний маршрут, который обрабатывает все ненайденные адреса. |
| **zentrale Fehlerbehandlung** | Общее место, где обрабатываются ошибки и отправляются ответы. |
| **In-Memory-Speicher** | Данные, которые находятся только в рабочей памяти запущенной программы. |
| **Postman** | Программа для отправки и тестирования запросов к API. |
| **Pre-request** | Скрипт, который выполняется перед запросом. |
| **Response-Test** | Автоматический тест на содержание и статус ответа. |

## Аутентификация и сеансы

| Термин | Краткое определение  |
|---|---|
| **Authentifizierung** | Проверка того, кто является пользователем. |
| **Autorisierung** | Проверка того, что пользователю разрешено делать. |
| **Identität** | Информация, которая однозначно описывает человека или систему. |
| **Passwort-Hash** | Проверочное значение пароля, которое нельзя напрямую преобразовать обратно. |
| **Salt** | Случайное дополнение к паролю перед хешированием. |
| **Hashing** | Преобразование данных в проверочное значение фиксированной длины. |
| **Argon2id, scrypt, bcrypt** | Безопасные методы хеширования паролей. |
| **Brute Force** | Атака, при которой перебирается множество возможных паролей. |
| **Credential Stuffing** | Атака с использованием украденных учетных данных из других сервисов. |
| **Phishing** | Попытка обмануть людей, чтобы они раскрыли конфиденциальные данные. |
| **Session** | Управляемое состояние входа пользователя на стороне сервера. |
| **Session-ID** | Случайный идентификатор, связывающий клиента с сеансом. |
| **Session-Store** | Хранилище сессий и связанных с ними данных. |
| **Cookie** | Небольшой фрагмент информации, который браузер хранит для веб-страницы. |
| **Session-Cookie** | Файл cookie, содержащий идентификатор сеанса. |
| **`HttpOnly`** | Запрещает доступ к файлам cookie с помощью JavaScript. |
| **`Secure`** | Позволяет отправлять файлы cookie только по протоколу HTTPS. |
| **`SameSite`** | Определяет, когда файл cookie отправляется на сторонние веб-сайты. |
| **Session Fixation** | Атака с предопределенным идентификатором сеанса. |
| **Session Hijacking** | Несанкционированный захват чужой сессии. |
| **Session-Regeneration** | Создание нового идентификатора сеанса после важного действия. |
| **Session-Timeout** | Автоматическое завершение сеанса по истечении определенного времени. |
| **Sliding Expiration** | Продлевает срок сессии при дальнейшей активности пользователя. |
| **Bearer Token** | Токен, дающий доступ его владельцу. |
| **Passkey** | Безопасный вход с криптографической парой ключей. |
| **WebAuthn** | Веб-стандарт для безопасного входа с помощью ключей доступа и устройств. |
| **Clerk** | Сервис для входа в систему и управления пользователями. |
| **Auth-as-a-Service** | Внешняя служба обрабатывает аутентификацию и управление пользователями. |
| **Vendor Lock-in** | Сильная зависимость от конкретного провайдера. |

## Безопасность JWT и токенов

| Термин | Краткое определение  |
|---|---|
| **JWT-Header** | JSON Web Token Header – часть JWT с информацией о типе и способе подписи. |
| **JWT-Payload** | JSON Web Token Payload – часть JWT, содержащая утверждения (claims). |
| **Claim** | Отдельное утверждение или информация в токене. |
| **JWT-Signature** | JSON Web Token Signature – защищает JWT от незаметных изменений. |
| **Base64URL** | Base64 Uniform Resource Locator Encoding – безопасная для URL кодировка двоичных данных. |
| **JWS** | JSON Web Signature – стандарт для данных с цифровой подписью. |
| **`HS256`** | HMAC using SHA-256 – способ подписи с общим секретным ключом. |
| **`RS256`** | RSA Signature with SHA-256 – способ подписи с закрытым и открытым ключами. |
| **`sub`** | Claim, который указывает идентификатор владельца токена. |
| **`iss`** | Claim, который указывает издателя токена. |
| **`aud`** | Claim, который указывает предполагаемого получателя токена. |
| **`exp`** | Claim, который указывает время окончания действия токена. |
| **`nbf`** | Claim, который указывает, с какого времени токен действителен. |
| **`iat`** | Claim, который указывает время создания токена. |
| **`jti`** | Уникальный идентификатор для JWT. |
| **`jsonwebtoken`** | Библиотека Node.js для создания и проверки JWT. |
| **`jwt.sign()`** | Создаёт и подписывает JWT. |
| **`jwt.verify()`** | Проверяет подпись и действительность JWT. |
| **`jwt.decode()`** | Читает JWT без проверки его подписи. |
| **Refresh Token** | Долгоживущий токен для запроса новых токенов доступа. |
| **Token-Rotation** | При каждом обновлении выдаётся новый refresh-токен. |
| **Token-Widerruf** | Токен становится недействительным до окончания срока действия. |

## Безопасность API и CORS

| Термин | Краткое определение  |
|---|---|
| **Angriffsfläche** | Все точки системы, которые могут быть атакованы. |
| **Input Validation** | Проверка соответствия входных данных ожидаемому формату. |
| **Parsing** | Преобразование текстовых данных в пригодную для использования структуру. |
| **Normalisierung** | Входные данные приводятся к единой форме. |
| **Positivliste / Whitelist** | Действительны только явно разрешенные значения или действия. |
| **Negativliste / Blacklist** | Определённые известные значения или действия запрещены. |
| **Injection** | Вредоносный ввод изменяет команду или запрос. |
| **SQL Injection** | Вредоносный SQL-код внедряется через входные данные. |
| **NoSQL Injection** | Вредоносные входные данные изменяют NoSQL-запрос. |
| **Command Injection** | Входные данные запускают неразрешённые команды операционной системы. |
| **Broken Object Level Authorization** | Пользователь может без разрешения получить доступ к чужим объектам. |
| **Broken Object Property Level Authorization** | Пользователь может читать или изменять отдельные свойства без разрешения. |
| **Mass Assignment** | Непроверенные входные данные изменяют также запрещённые поля объекта. |
| **Data Minimization** | Обрабатываются только действительно необходимые данные. |
| **Rate Limiting** | Количество запросов ограничено за период. |
| **Unrestricted Resource Consumption** | Отсутствие ограничений приводит к чрезмерному потреблению ресурсов. |
| **Sicherheits-Fehlkonfiguration** | Небезопасные настройки делают систему уязвимой. |
| **Same-Origin-Prinzip** | Браузеры ограничивают доступ между разными origin. |
| **Origin** | Комбинация протокола, хоста и порта адреса. |
| **Cross-Origin-Request** | Запрос к другому origin. |
| **CORS-Header** | Cross-Origin Resource Sharing Header – HTTP-заголовки, задающие разрешённый доступ между источниками. |
| **Preflight** | Автоматический OPTIONS-запрос для проверки CORS-доступа. |
| **`Access-Control-Allow-Origin`** | Указывает, какому источнику разрешен доступ к ответу. |
| **`Access-Control-Allow-Methods`** | Задает разрешенные HTTP-методы для CORS-запросов. |
| **`Access-Control-Allow-Headers`** | Задает разрешенные заголовки запросов для CORS-запросов. |
| **HTTPS/TLS** | Hypertext Transfer Protocol Secure / Transport Layer Security – шифрует соединение между клиентом и сервером. |
| **Logging** | Систематическое хранение важных событий. |
| **Monitoring** | Постоянное наблюдение за состоянием, производительностью и ошибками. |
| **Deny by default** | Доступ запрещен до тех пор, пока не будет прямо разрешен. |
| **Never trust the client** | Все данные от клиента должны быть проверены на сервере. |
