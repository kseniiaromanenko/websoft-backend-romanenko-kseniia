# Итоговый проект по модулю Backend

## Обзор проекта

- Спроектируй, разработай, защити, протестируй, задокументируй и разверни готовый к эксплуатации REST API.
- Выбери содержательную задачу и подходящую предметную область для своего API.
- Проект должен продемонстрировать знания в области Backend, полученные тобой в ходе модуля, включая проектирование API, постоянное хранение данных, связанные модели данных, аутентификацию и авторизацию, валидацию, тестирование и развертывание.

## Требования к проекту

### 1. Спланируй API до начала реализации

- До разработки API задокументируй его назначение и архитектуру.
- Учти следующее:
  - Какую проблему решает твой API и кто будет им пользоваться?
  - Как минимум две связанные сущности и отношения между ними.
  - Диаграмма «сущность — связь» (ERD) или эквивалентная диаграмма модели данных.
  - Планируемые эндпоинты, HTTP-методы и назначение каждого эндпоинта.
  - Примеры форматов запросов и ответов, включая ответы с ошибками.
  - Подход к аутентификации и авторизации, если это применимо.
  - Выбранный технологический стек и краткое обоснование каждого важного решения.

### 2. Разработай полноценный REST API

- Реализуй целостный API для выбранной предметной области.
- Он должен:
  - Использовать постоянную базу данных для хранения и получения данных.
  - Моделировать как минимум две связанные сущности и реализовывать отношения между ними в базе данных и API.
  - Предоставлять подходящие REST-эндпоинты для основных сценариев использования, включая создание, чтение, обновление и удаление, если эти операции имеют смысл для выбранной предметной области.
  - Использовать подходящие HTTP-методы и коды состояния, а также возвращать согласованные JSON-ответы.
  - Поддерживать фильтрацию, поиск или пагинацию, если это целесообразно для твоего API.
  - Иметь четкую модульную структуру с понятным и удобным для сопровождения распределением ответственности.

### 3. Обеспечь безопасность API

- Примени изученные в модуле методы обеспечения безопасности, которые актуальны для твоего API.
- Как минимум:
  - Проверяй и, где это целесообразно, очищай недоверенные входные данные.
  - Защищай маршруты и данные, которые не должны быть общедоступными.
  - Настрой CORS специально для клиентов, которым необходим доступ.
  - Используй ограничение частоты запросов (Rate Limiting) для защиты чувствительных или уязвимых для злоупотреблений эндпоинтов.
  - Обрабатывай ошибки, не раскрывая клиентам API трассировки стека, секреты и другие внутренние сведения.
  - Используй безопасные настройки развертывания и HTTPS для развернутого API.

- Объясни, какие меры безопасности неактуальны для твоей архитектуры, и обоснуй это решение.

### 4. Протестируй и задокументируй API

- Напиши автоматизированные тесты для важных сценариев, включая успешные запросы, некорректные входные данные и актуальные случаи авторизации или ошибок.
- Задокументируй локальную установку, настройку, тестирование и запуск проекта.
- Задокументируй эндпоинты API и приведи примеры запросов и ответов, включая ожидаемые случаи ошибок.
- Добавь план проекта и диаграмму модели данных в репозиторий или размести ссылки на них в файле README.
- Убедись, что другие разработчики могут следовать документации и опробовать API.

### 5. Разверни Backend

- Разверни API так, чтобы преподаватель мог получить к нему доступ.
- Проверь, что развернутый сервис корректно запускается и задокументированные эндпоинты работают.
- Добавь URL работающего Backend в отправляемую работу и файл README.
- Не публикуй учетные данные или конфиденциальные значения конфигурации в репозитории или документации.

## Критерии готовности (Definition of Done)

Проект считается завершенным, если:

- API охватывает четко описанный сценарий использования и содержит как минимум две связанные сущности.
- Основные данные хранятся постоянно, а API поддерживает необходимые операции создания, чтения, обновления и удаления.
- API протестирован, а важные меры безопасности реализованы и объяснены.
- Проект задокументирован так, чтобы другие разработчики могли настроить его и использовать API.
- Backend развернут, публичный URL работает и передан преподавателю.
- Все участники могут объяснить архитектуру, модель данных, эндпоинты, решения по безопасности, тесты, развертывание и собственный вклад.
